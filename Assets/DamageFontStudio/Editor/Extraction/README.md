# 영상에서 데미지 연출 추출

## 원본의 연타 시각을 보존하는 자동 추출

추출 창 위쪽에서 다음 순서로 진행합니다.

1. **영상 불러오기...**로 영상을 먼저 불러옵니다. 이 단계에서는 분석하거나 샘플을 생성하지 않습니다.
2. 오른쪽 미리보기에서 재생·프레임 이동으로 구간을 확인하고 **현재를 시작으로 / 현재를 종료로**를 누릅니다. **분석 시작 / 종료 (초)**에 직접 입력할 수도 있습니다. 처음 불러오면 영상 전체가 선택되며 분석 구간은 0.3초 이상이어야 합니다. 수동 추출과 같은 시작·종료 프레임을 사용합니다.
3. **분석 시작 → 샘플 자동 생성**을 누르면 선택한 구간의 분석과 프리셋·샘플 생성이 이어집니다. 취소하면 선택한 구간의 미리보기로 돌아가 다시 실행할 수 있습니다.

### 원하는 화면 영역만 분석

시간 구간을 정한 다음 **분석 영역 제한**을 켜고, 원본 미리보기에서 원하는 영역을 드래그합니다. 녹색 테두리 안이 분석 영역이며 바깥은 어둡게 표시됩니다. **분석 영역 지정**으로 다시 그리거나 **분석 영역 (원본 픽셀)**에서 X/Y/너비/높이를 직접 조정할 수 있습니다. **전체 화면 사용**은 영역 제한을 해제합니다. 드래그 도중 Esc는 지정을 취소하며 마지막으로 확정한 영역을 유지합니다.

원하는 숫자가 나타나서 이동하는 경로 전체를 포함하도록 영역을 잡은 뒤 **분석 시작 → 샘플 자동 생성**을 누릅니다. 영역을 정하는 동안 분석은 시작되지 않습니다. 영역 밖 문자 픽셀을 가리고 후보 검출·반복 타격 재검출·앞뒤 추적·추정 복원에 같은 경계를 적용합니다. 잘린 숫자 조각이 다른 연출로 섞이는 것을 줄이기 위해 테두리에 닿는 숫자도 제외합니다. 숫자가 영역 밖으로 나간 이후의 움직임은 결과에 넣지 않으며, 경계에서 잘린 종료를 실제 페이드 소멸로 간주하지 않습니다.

영역은 원본 영상 좌표에 고정됩니다. 미리보기 확대·창 크기·나란히 비교에 따라 좌표가 바뀌지 않으며, 시간 구간과 함께 각 세션 및 `Analysis.json`에 저장됩니다. 영역 안에서 겹치는 다른 연출은 공간 선택만으로 구분되지 않을 수 있으므로 원하는 연출이 잘 분리되는 시간과 영역을 함께 선택하세요. 배경 흔들림 추정에는 원본 전체의 배경을 사용하고, 데미지 문자 분석에는 선택 영역만 사용합니다. **수동 추출 / 보정**의 숫자 상자 지정은 별도 기능으로 유지됩니다.

**화면 흔들림 제거**는 기본으로 켜져 있습니다. 배경의 공통 가로·세로 이동을 추정하고 각 숫자의 이동에서 빼서 게임용 프리셋에 저장합니다. 숫자 자체의 상승·하강·가로 이동, 크기, 투명도와 타격 간격은 유지합니다. 원본 좌표와 추정한 배경 이동은 세션에 함께 보존합니다. 기존 결과물은 다시 분석해야 보정된 프리셋이 생성됩니다.

지정한 시작·종료 시점을 분석·학습·저장·전체 재생의 경계로 사용합니다. 범위 밖 프레임은 분석에 사용하지 않습니다. 종료 시점에 아직 보이는 숫자도 그 시점에서 재생을 끝내며, 실제 소멸을 관측한 것으로 표시하지 않습니다. 밝은색·분홍색의 어두운 외곽선이 있는 이동형 데미지 숫자가 현재 검출 대상입니다.

분석은 로컬 PP-OCR 단어 영역·숫자 판독 + 색상/외곽선 타격 후보 검출 → 영상에서 선명하게 관측한 숫자 템플릿으로 겹친 반복 타격 재검출 → 전방 이동·크기·대비 측정 → 역방향 등장 시점 복구 순서입니다. 같은 숫자가 아래에서 새로 등장하면 이전 숫자의 수명을 연장하지 않고 별도 타격으로 처리합니다. 밝은 공격 이펙트가 템플릿에 섞이는 것을 줄이기 위해 숫자의 연결 영역과 외곽선 대비를 사용합니다. 검출이 끊기는 시점을 기록하며, 기존처럼 마지막 검출 뒤 2프레임의 페이드를 일괄 추가하지 않습니다. 선명한 큰 등장 장면만 관측되고 곧바로 다음 타격에 가려지는 숫자는 같은 종류의 충분히 관측된 연출로 이어서 재구성합니다. 이런 경우 `motionInferred=true`, `observedDisappearance=false`로 기록하여 실측 소멸과 구분합니다.

평가 대상은 폰트 외형이나 판독한 숫자가 아닌 **등장 간격·X/Y 궤적·상대 크기·투명도·종료 시점**입니다. 관측된 각 타격의 화면 좌표·크기·알파 측정점을 시간 순서대로 내보내고 구간 사이를 보간합니다. 수평 이동, 상승 후 하강, 좌우 전환을 보존하며 포물선이나 직선 같은 특정 모양을 강제하지 않습니다. 같은 색상의 타격도 서로 다른 궤적을 유지하며 색상별 평균 연출로 덮어쓰지 않습니다. 숫자의 폭이나 자릿수는 이동 채널에 사용하지 않습니다. 가려진 짧은 타격의 추정 복원에만 같은 종류의 관측으로 학습한 보조 궤적을 사용할 수 있으며 `motionInferred`와 `sharedMotion`으로 표시합니다.

일반 MP4/MOV에서는 `stts`, `ctts`, 지원되는 `elst`를 읽어 실제 표시 시각을 사용합니다. 평균 FPS로 프레임 시각을 환산하지 않습니다. 지원하지 않는 컨테이너·편집 목록·분할 MP4에서는 디코더 시각으로 돌아가며 `Analysis.json`에 시간 기준을 기록합니다. 영상은 업로드하거나 프로젝트로 복사하지 않습니다.

### 생성되는 데이터

`Assets/DamageFontStudio/Generated/Video-*`에 다음을 새로 저장합니다. 기존 에셋은 덮어쓰지 않습니다.

- **GameMotion.asset**: 게임에 연결할 최종 연출 파일 하나입니다. 기본값은 추정 복원보다 관측된 타격, 종료가 관측된 타격, 높은 추적 적합도를 우선해 하나를 선택합니다. 선택한 타격을 그대로 복사하며 여러 타격을 평균으로 합치지 않습니다. 최종본을 직접 편집한 뒤 다시 열어도 자동으로 덮어쓰지 않습니다.
- **RecordedHits.asset**: 타격마다 다른 등장 시각·위치·프리팹을 저장한 분석 비교 시퀀스입니다. 각 타격이 서로 다르게 재생될 수 있으므로 단일 게임 적용 연출은 GameMotion으로 확인합니다.
- **Analysis/Light-XX / Pink-XX-Motion.asset**: 타격별 연출 후보입니다. 번호는 타격의 식별자이며 버전 번호가 아닙니다. 각 타격의 독립적인 측정 궤적을 보존합니다.
- **Analysis/Light-XX / Pink-XX.asset, .prefab, -Outline.mat**: 원본 비교를 위한 타격별 샘플 외형과 연출입니다.
- **Analysis/*-Session.asset**: 원본 측정점, 실제 시각, 템플릿 적합도, 소멸 관측 여부 및 불확실한 숫자 판독을 보존합니다.
- **Analysis/Analysis.json**: 시간 기준, 타격 시각, 길이, 템플릿 적합도, 소멸 관측 여부와 판독 추정을 기록합니다. `initialGameMotionSourceIndex`는 자동 생성 직후 선택된 원본 타격입니다. 이후 선택 변경은 GameMotion의 원본 타격 표시를 따릅니다. 적합도는 정답 확률이 아닙니다.

기존 분석 폴더의 파일 구조는 유지합니다. RecordedHits Inspector의 **게임 적용본 생성 후 재생 테스트**로 같은 폴더에 GameMotion을 추가할 수 있습니다. 재분석할 필요는 없습니다.

### 게임 적용 최종본 재생 테스트

분석이 완료되면 GameMotion을 선택하고 재생 테스트를 엽니다. 파일을 더블클릭하거나 추출 창·RecordedHits Inspector의 **게임 적용 최종본 재생 테스트**를 눌러 다시 열 수 있습니다. **기존 게임 데미지 프리팹 / 오브젝트**에 게임의 프리팹을 지정하고 숫자를 바꾼 뒤 단발·연타·동시 재생·시간 이동으로 확인합니다. 여기서 사용하는 `.asset`과 게임의 `DamageFontObject.Preset`에 연결할 `.asset`은 동일한 파일입니다. 프리팹이 지정되지 않았으면 기본 텍스트를 사용한다고 명시합니다.

**타격별 분석 결과 / 최종본 변경**을 펼치면 타격 이름, 영상 내 시작 시간, 길이와 종료 관측/잘림/추정 상태를 확인할 수 있습니다. **이 타격 연출 확인**은 후보를 재생하고, **이 연출을 최종본으로 지정**은 그 후보를 GameMotion에 복사한 뒤 최종 파일을 재생합니다. 파일 GUID를 유지하므로 게임에서 연결한 프리셋을 다시 바꿀 필요가 없습니다.

### 원본과 같은 시간축으로 비교

**전체 결과만 재생 테스트에서 보기**: `RecordedHits.asset`을 선택하고 Inspector의 **재생 테스트에서 전체 재생**을 누릅니다. Studio의 **재생 테스트 → 추출된 연타 시퀀스** 필드에 RecordedHits를 지정해도 됩니다. **전체 시퀀스 재생**, 일시정지·재개, 반복, 배속, 시간 이동과 숫자 변경을 지원합니다. 타격별 프리팹과 기록된 간격을 지정한 구간 안에서 재생합니다. 원본 영상이나 디코더는 사용하지 않습니다. 표시할 숫자를 비우면 타격별 저장된 숫자를 사용합니다. **프리셋 제작 / 테스트**로 전환하면 기존 제작 옵션과 테스트 설정으로 돌아갑니다. 전체 재생 중에도 **편집할 타격**으로 개별 프리셋을 수정할 수 있습니다.

자동 생성이 끝나면 비교 창이 열립니다. 다시 열 때는 **RecordedHits.asset**을 선택하고 Inspector의 **원본과 연타 시퀀스 비교**를 누릅니다. 또는 추출 창의 **추출된 연타 시퀀스**에 에셋을 지정합니다. **원본 / 추출 결과** 모드에서는 왼쪽 원본과 오른쪽 추출 숫자만 같은 프레임으로 보여줍니다. 오른쪽에는 원본 숫자를 합성하지 않습니다. **구간 재생**, 프레임 이동, 배속을 공통으로 적용합니다. 재생은 실제 시간에 맞춰 진행하며 디코딩이 느리면 표시 프레임을 건너뜁니다. 정확한 프레임 검토는 일시정지 후 좌우 이동으로 확인합니다. 수동 영역 입력은 기본으로 접힌 **수동 추출 / 보정**에 있습니다.

흔들림을 제거한 결과는 Studio와 원본 비교에서 기본적으로 보정된 움직임으로 재생합니다. **원본 비교에 화면 움직임 포함**을 켜면 비교 창에만 배경 이동을 다시 더해 원본 화면 좌표와 대조할 수 있습니다. 이 옵션은 게임용 프리셋을 변경하지 않습니다.

### 게임 적용 파일

**게임에서 이미 쓰는 데미지 폰트 프리팹을 유지하고, 추출한 연출만 적용하는 것이 기본 규칙입니다.**

- 게임용 결과는 최종 파일 `GameMotion.asset`입니다. 이 파일에는 샘플 폰트·머티리얼 참조와 RGB 색상 변경이 없으며, 샘플 글꼴에 맞춘 최초 가로 배율도 제거합니다. 게임 프리팹의 원래 외형을 기준으로 상대 이동·상대 크기 변화·회전·투명도만 적용합니다.
- 기존 프리팹에 `DamageFontObject`를 연결하는 경우 **Preset**에 `GameMotion.asset`을 넣고 `Play(damage.ToString())`를 호출합니다. 기존 게임 코드에서 직접 연결할 경우 `new DamageFontPlayback(existingObject, numberText, overrideTextAppearance: false)`에 같은 최종 프리셋을 전달합니다. 게임 프리팹을 생성된 샘플로 교체하지 않습니다.
- 기록한 연타 전체도 게임 프리팹으로 재생할 수 있습니다. `new DamageFontSequencePlayback(recordedHits, parent, "1234", targetPrefab: existingGamePrefab)`를 사용하면 타격별 `motionPreset`을 기존 게임 프리팹의 복제본에 적용합니다. 경과 시간을 `Seek(time)`에 전달하고 종료 시 `Dispose()`합니다. 게임 프리팹에 `DamageFontObject`가 없어도 첫 TMP 텍스트에 값을 표시할 수 있습니다.
- 생성된 `.prefab`과 외형을 포함한 `Light-01.asset` 등은 원본 비교·샘플 확인용입니다. `RecordedHits.asset`에는 타격별 시간과 모션 참조가 들어 있으며, 개별 피격 연출만 적용할 때는 필요하지 않습니다.
- 게임에는 `GameMotion.asset`, `DamageFontStudio/Runtime` 코드와 DOTween·TextMeshPro를 포함합니다. 원본 영상, 생성된 샘플 폰트·머티리얼·프리팹, 세션, 분석 JSON과 Editor 분석 모델은 개별 모션 재생에 필요하지 않습니다. 추출 좌표는 영상 픽셀 기준이므로 게임의 UI/월드 단위에 맞게 이동 단위를 조정합니다.

숫자 입력란을 비우면 타격별 추정 숫자 또는 대체값을 사용합니다. 값을 입력하면 모든 타격의 숫자를 바꿉니다. 단일 프리팹을 Studio에서 미리보기할 때도 같은 폴더에 시퀀스가 있으면 **원본과 연타 시퀀스 비교** 버튼이 표시됩니다.

Studio의 기존 **연타**는 사용자가 지정한 일정 간격의 반복 테스트입니다. 영상에서 관측한 불규칙한 연타 간격을 비교하려면 **RecordedHits**를 사용합니다. 런타임에서는 `DamageFontSequencePlayback(sequence, parent, "12345")`를 만들고 `Seek(elapsedSeconds)`로 같은 공통 재생 코드를 사용할 수 있습니다. 사용을 마치면 `Dispose()`합니다.

### 좌표, 외형과 남은 한계

**시작 X 위치 고정**은 타격들이 태어나는 좌표만 맞춥니다. 시작 후의 X/Y 이동은 그대로 재생합니다. RecordedHits의 `lockSpawnX`와 `spawnX`로 제어하며 비교 창에서도 바꿀 수 있습니다. 끄면 저장된 원본 시작 좌표를 사용합니다. 원본은 카메라 이동 등으로 타격별 시작 좌표가 다를 수 있으므로 원본 화면 위치까지 비교할 때는 이 옵션을 끕니다. Studio의 임의 분산은 기본적으로 꺼져 있습니다.

폰트 크기는 TMP의 SDF 패딩이 포함된 메시 사각형 대신 글자 획의 치수와 기울기를 기준으로 보정합니다. 원본 폰트를 복원하는 기능은 아니며 Liberation Sans의 굵은 기울임과 어두운 외곽선으로 근사합니다. 숫자 내용은 로컬 PP-OCR 판독과 글꼴 템플릿으로 추정하며 판독이 불확실하면 `189`를 사용합니다. 판독은 타격 시각이나 움직임을 결정하지 않습니다.

완전히 가려진 숫자, 서로 붙은 숫자, 흰색 공격 섬광, 배경 변화가 심한 구간에서는 검출 누락과 추적 혼선이 남을 수 있습니다. 배경에 합성된 알파는 대비 기반 추정값이며 원본 알파와 동일하다고 보장하지 않습니다. 원본/추출 결과를 직접 비교하여 누락과 오검출을 확인해야 합니다. 화면 흔들림 제거는 추정한 배경 평행이동을 보정하며 회전·줌·원근 차이·세계 좌표는 복원하지 않습니다.

분석 취소, 창 종료, Play 모드 전환, 스크립트 리로드 시 디코더와 임시 자원을 해제합니다. `DamageVideoFidelityVerification.Run`은 별도 검증 프로젝트에서 실제 분석·같은 시각의 원본/추출 렌더·타격 분리·대비 추정·기존 재생 회귀 검사를 실행합니다. `DamageVideoDecoderVerification.Run`은 독립적으로 디코딩한 정답 이미지와 요청 프레임의 픽셀을 비교합니다. 템플릿 적합도를 실제 영상 인식 정확도인 것처럼 사용하지 않습니다.

## 수동 영역 지정 및 보정

자동 생성의 **시작 X 위치 고정**은 기본으로 켜져 있습니다. 단일 프리셋에는 원본의 상대 X/Y 이동을 항상 저장하며 이 옵션으로 제거하지 않습니다. Studio 연타는 동일 위치에서 생성하며 **생성 위치 무작위 분산**을 직접 켠 경우에만 타격별 시작점에 분산을 더합니다. 이전 버전에서 X 이동이 제거되거나 평균 연출로 덮인 에셋은 다시 분석해 생성해야 합니다. 저장된 수동 세션은 프리셋을 다시 내보내면 측정 X 이동을 복구할 수 있습니다.

## 열기

창 상단 **언어 / Language**에서 한국어와 영어를 전환합니다. 기본값은 한국어이며 Studio 및 관련 Inspector와 같은 설정을 사용합니다. 선택한 언어는 다음 실행에도 유지됩니다. 아래 버튼 이름은 English 표시 기준입니다.

Studio 상단 **Extract from video**, 또는 **Tools > Damage Font Studio > Extract From Video**를 누릅니다. Play 모드를 종료한 상태에서 사용합니다. 기존 Studio와 동일한 IMGUI 편집 환경입니다.

## 1. 영상과 구간 선택

1. **Open video...**에서 로컬 영상을 선택합니다. H.264 MP4 / 고정 프레임레이트(CFR)를 권장합니다. 코덱 지원은 Unity/운영체제에 따릅니다. 각 변 4096픽셀 이하를 지원합니다. 영상은 업로드하거나 Assets로 복사하지 않습니다.
2. Frame 슬라이더, `<` / `>`로 프레임을 탐색합니다. 실제 디코딩이 끝난 프레임 번호가 화면 위에 표시됩니다.
3. 숫자가 나타나는 프레임에서 **Set Start here**, 사라지는 프레임에서 **Set End here**를 누릅니다. 처음에는 1~2초 구간과 숫자 한 개로 시작하세요. End는 프리셋이 숨겨지는 시점입니다.
4. Start 프레임으로 돌아가 **Draw / replace number region**을 켜고 숫자를 타이트하게 둘러싸는 사각형을 드래그합니다. 배경이 많이 포함될수록 배경을 추적하기 쉽습니다.

## 2. 자동 추적 제안

**Track forward from current frame**을 누르면 현재 프레임부터 End까지 위치와 균일 크기 변화를 추정합니다. 로컬 명암 템플릿 비교 방식이며 OCR이나 원본 설정 복원은 아닙니다. 새 외부 라이브러리 설치 없이 Unity 내에서 동작합니다.

- Sample every N frames: 낮을수록 빠른 움직임을 더 촘촘하게 기록합니다. 기본 2.
- Search radius: 이전 위치 주변의 탐색 반경(원본 픽셀). 빠른 이동은 반경을 키우거나 샘플 간격을 줄이세요.
- Stop below confidence: 비교 점수가 낮으면 해당 결과를 남기고 멈춥니다. 점수는 정답 확률이 아닙니다. 배경을 잘못 따라가면서 점수가 높을 수도 있으니 반드시 확인하세요.
- Stop tracking: 이미 얻은 결과를 유지하고 중단합니다.
- 하나의 프리셋에 최대 600개 샘플을 사용합니다.

## 3. 수정하고 이어가기

**Previous sample / Next sample**로 이동합니다. 틀린 프레임에서 영역을 다시 그리거나 다음 값을 수정합니다.

- Center: 원본 영상 픽셀 기준 중심점. 왼쪽 위가 (0, 0), 아래가 +Y.
- Unrotated box size: 회전 전 숫자 영역의 폭과 높이. 첫 샘플에 대한 비율이 Scale로 변환됩니다.
- Rotation clockwise: 시계방향 각도. 회전은 자동 추정하지 않습니다. 360도 이상 회전은 연속된 각도로 입력하세요.
- Opacity: 직접 지정하는 0~1 값. 영상의 배경과 합쳐진 알파를 자동 복원하지 않습니다.

수정한 프레임은 수동 기준점(청록색)이 됩니다. **Track forward**로 다시 추적하면 이후 자동 결과를 갱신하고, 이미 만든 수동 기준점은 보존하며 그 지점에서 추적 기준을 다시 잡습니다. 수정만 하고 추적을 다시 하지 않으면 기존 이후 샘플은 그대로 유지됩니다.

샘플이 없는 프레임의 값은 주변 샘플을 선형 보간합니다. **Pin interpolated frame as manual anchor**로 보간 값을 실제 기준점으로 확정할 수 있습니다. 숫자가 사라져 End까지 추적하지 못했다면 End에서 보간 값을 Pin하고 Opacity를 0으로 설정하세요. Start와 End에 샘플이 있어야 내보낼 수 있습니다. Undo/Redo를 지원합니다.

## 4. 원본과 비교

- Original + track: 원본과 추적 사각형.
- Overlay preset: 원본 위에 추출 프리셋의 실제 DOTween/TMP 재생 결과를 합성.
- Side by side: 왼쪽 원본, 오른쪽 원본+합성 결과.
- Overlay blend: 비교용 텍스트의 합성 강도. 프리셋 투명도에는 저장되지 않습니다.
- Number text / TMP font / color: 비교에 사용할 숫자와 외형을 선택합니다. 영상 속 폰트를 추출하지 않습니다.
- Play range: 프레임을 차례대로 디코딩하며 재생합니다. 코덱/탐색 속도에 따라 지정 배속보다 느릴 수 있습니다.

비교 텍스트의 초기 크기는 첫 숫자 박스에 맞춰집니다. 이 맞춤은 영상 비교용입니다. 실제 프리팹에서는 폰트/외곽선/자식 배치가 다를 수 있으므로 첫 프레임의 외형을 따로 맞추세요. 위치·크기·회전·알파 변화는 같은 공통 재생 코드를 사용합니다. 추적된 위치에는 카메라 움직임도 포함되며 월드 좌표나 카메라 보정은 자동 복원하지 않습니다.

## 5. 저장과 재사용

**Save session...**은 영상 경로, 구간, 추적 샘플, 보정값과 비교 설정을 편집용 `.asset`으로 저장합니다. 나중에 Session 필드로 불러오고 **Reopen / relink**로 영상을 연결하세요. 원본 영상을 옮겼다면 같은 영상을 다시 선택합니다. 해상도·프레임 수·fps가 다르면 기존 세션에 연결하지 않습니다.

**Save animation preset (.asset)...**은 기존 `DamageFontPreset` 형식으로 별도 저장합니다. 기본 선형 구간들을 사용하여 X/Y의 움직임, 크기, 회전, 수동 알파를 재현하므로 런타임에 영상/세션/추적 코드가 필요 없습니다. Units per source pixel은 영상 픽셀을 Unity 로컬 단위로 바꾸는 배율입니다. UI는 1부터 시작하고 월드 오브젝트는 크기에 맞춰 낮추세요.

저장된 프리셋을 기존 Studio의 Preset에 지정하여 재생하거나 `Damage Font Object`에 연결합니다. 세션 수정 후 프리셋을 다시 내보내야 수정이 반영됩니다. 세션과 프리셋 저장은 별개입니다. 세션은 Editor 폴더의 타입이므로 게임 런타임에서 참조하지 마세요.

## 범위와 한계

배경이 복잡하거나 숫자가 겹치고 모양이 바뀌는 장면에서는 직접 보정이 필요합니다. 자동 추적은 위치와 균일 크기를 제안하며 회전·알파는 수동입니다. 발광·외곽선 셰이더·폰트 파일·숫자별 분리 애니메이션·카메라 움직임 제거는 이번 구현 범위가 아닙니다. 지원되는 MP4/MOV는 실제 표시 시각을 사용합니다. 지원하지 않는 시간 테이블의 영상은 고정 fps 영상으로 변환한 뒤 다시 비교하세요.

영상 준비/탐색은 VideoPlayer.seekCompleted 이후 렌더 반영을 기다려 처리하며 마지막 프레임은 디코더의 종료까지 확인합니다. 평균 FPS 기반 프레임 번호로 다시 탐색하지 않습니다. 창 종료, Play 모드 전환, 스크립트 리로드 시 디코더와 미리보기 Scene/트윈/RenderTexture를 해제합니다.

검사 메뉴: **Tools > Damage Font Studio > Run Video Extraction Checks** (세션/변환/재생 검사). 개발 시 합성 영상 통합 검사는 `DamageVideoVerification.RunFixtureChecks`에서 실행하며 결과는 `Logs/VideoExtractionChecks`에 저장합니다.

## 로컬 분석 의존성

자동 분석은 프로젝트에 설치된 `com.unity.ai.inference` 2.6.1에서 Editor 전용 PP-OCRv3 ONNX 모델을 실행합니다. Python, 별도 서버, 영상 업로드는 필요하지 않습니다. Compute Shader가 지원되는 환경에서는 영상에서 관측한 단어 템플릿을 GPU로 재탐색합니다. 지원되지 않으면 기본 검출·추적 경로를 사용합니다. 모델은 `Editor/Models`에 있으며 출처·SHA256·Apache 2.0 라이선스를 함께 보관합니다. 내보낸 프리셋/프리팹/RecordedHits의 런타임 재생에는 모델이나 추출 Editor 코드가 필요하지 않습니다.
